# Аудит Шабашки

Роль: продуктовый аналитик и SMM-стратег. Задача — проверить сайт, бота и контент и найти решения, которые дадут больше откликов, подписчиков и заказов. **Только анализ: код не менять, ничего не коммитить.**

Если в `$ARGUMENTS` указана область (например «только контент»), проверяй только её, а остальное пропусти.

## Контекст

- Шабашка — доска вакансий и подработок по Кыргызстану.
- Сайт шабашка.com — `frontend/` (Vite, Netlify). API — https://shabashka-zvkc.onrender.com, `backend/` (Render).
- Telegram-бот — `backend/src/telegram` (`bot.js`, `menu.js`).
- Автопостинг:
  - Threads, Instagram, Telegram-канал — `backend/src/social`;
  - WhatsApp-канал — `backend/src/whatsapp`.
- Промо-ролики и SMM-календарь — `promo/`. Правила в `promo/CLAUDE.md`.
- Прошлые исследования и планы — `docs/research`, `docs/plans`. **Прочитай их первыми и не повторяй уже сделанное.**
- Замер 21.10.2026:
  - Threads — 4201 подписчик, Instagram — 2773;
  - 536 вакансий за 5 дней → 112 просмотров карточек, у 85% ноль;
  - на бирже 0 задач;
  - UTM в ссылках постов нет.
- Свежие цифры владелец кладёт скриншотами в `docs/research/stats-*/`. Если их нет, работай без них, а выводы, которым нужны цифры, помечай «гипотеза».

## Запреты

- В `backend/.env` указана **боевая база данных**:
  - backend локально не запускать;
  - node-скрипты с модулями из `backend/src/db` не запускать;
  - в БД не писать.

  Можно: читать код, открывать сайт, отправлять GET-запросы к публичному API.
- Не запускать фронт на dev-сервере с боевым API — только на моках.
- Ничего не публиковать и не писать от имени владельца: Telegram, Threads, Instagram, WhatsApp.
- Условия владельца:
  - всё работает автоматически, ручного времени — ноль;
  - количество постов не уменьшать;
  - DM-бота не развивать;
  - пригласительные продвигать только через «Мои продукты».

## Скиллы — обязательны

Вызывай их через Skill по имени. В начале каждого этапа пиши, какой скилл применяешь.

0. `planning-with-files` — веди task_plan.md и findings.md.
1. `dispatching-parallel-agents` — три параллельных агента: Сайт, Бот, Контент. Каждому передай раздел «Запреты» целиком.
2. **Сайт:**
   - `anthropic-skills:built-in-browser` — пройди путь «пост → карточка → отклик или контакт» на ширине телефона;
   - `impeccable` — UX-аудит;
   - `marketing:seo-audit`;
   - `small-business:seo-ai-visibility`.
3. **Бот:**
   - `design:ux-copy` — тексты, кнопки, меню, первый запуск;
   - по коду посчитай, сколько шагов до публикации у работодателя и до отклика у соискателя.
4. **Контент:**
   - `small-business:content-strategy`;
   - `marketing:performance-report` — по цифрам из stats;
   - `marketing:competitive-brief` — job.kg, lalafo, diesel.elcat.kg, Telegram-каналы с вакансиями по КР.
5. **Выводы:**
   - `inversion-exercise` — проверь главные допущения, например «больше постов — больше подписчиков»;
   - `verification-before-completion` — у каждого вывода должно быть доказательство: `file:line`, URL или цифра. Без доказательства помечай «гипотеза».

Дополнительно, если оправдано:
- `anthropic-skills:deep-research` — глубокое исследование рынка (дорого);
- `design:accessibility-review`;
- `humanizer` — для текстов постов.

## Результат

Файл `docs/research/<ГГГГ-ММ-ДД>-audit.md`, не больше 2 страниц:

1. Воронка «пост → сайт → отклик или подписка»: где теряем людей, с цифрами.
2. Топ-10 решений таблицей: что сделать · доказательство · ожидаемый эффект · усилие (S/M/L) · ручное время владельца.
3. Матрица «эффект / усилие». Три первых пункта — «сделать на этой неделе».
4. Что НЕ делать и почему.
5. Каких метрик не хватает и как снимать их автоматически.

После этого **остановись и жди**, какие пункты выберет владелец. План внедрения — только потом, через `writing-plans`, затем `test-driven-development`.
