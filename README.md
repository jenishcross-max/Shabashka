# Шабашка КГ

Доска объявлений для поиска подработки и мастеров в Кыргызстане.

- **Заказчики** регистрируются и размещают заказы (нужен аккаунт).
- **Исполнители** ничего не регистрируют — они просто смотрят заказы и пишут заказчику
  напрямую в WhatsApp кнопкой на странице заказа.

Архитектура сделана как REST API + отдельный веб-фронтенд, чтобы тот же бэкенд
можно было потом переиспользовать для мобильного приложения на React Native.

## Стек

- **backend/** — Node.js, Express, SQLite (`better-sqlite3`), JWT-авторизация
- **frontend/** — React (Vite), React Router

## Локальный запуск

```bash
npm run install:all
```

В двух терминалах:

```bash
npm run dev:backend
```

```bash
npm run dev:frontend
```

Backend поднимется на `http://localhost:4000`, фронтенд — на `http://localhost:5173`
(Vite проксирует `/api` на бэкенд, см. `frontend/vite.config.js`).

Скопируйте `backend/.env.example` в `backend/.env` и задайте свой `JWT_SECRET`.

## Продакшн-сборка (один сервер)

```bash
npm run build
npm start
```

`backend/src/server.js` сам отдаёт собранный `frontend/dist` — то есть на проде
достаточно одного сервиса, слушающего один порт (`PORT`, по умолчанию 4000).

## Деплой на GitHub + Render

1. Запушьте репозиторий на GitHub.
2. На [render.com](https://render.com) создайте **New Web Service**, подключите репозиторий —
   Render подхватит `render.yaml` из корня (build: `npm run build`, start: `npm start`).
3. Render автоматически сгенерирует `JWT_SECRET`. При необходимости добавьте свои переменные окружения.
4. При каждом пуше в GitHub Render передеплоит сервис автоматически.

SQLite-файл хранится на диске сервиса (`backend/data`, примонтирован как persistent disk
в `render.yaml`), поэтому данные переживают редеплой.

## API (кратко)

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/api/auth/register` | публичный | регистрация заказчика |
| POST | `/api/auth/login` | публичный | вход |
| GET | `/api/auth/me` | по токену | текущий пользователь |
| GET | `/api/orders` | публичный | список заказов (фильтры: `category`, `city`, `q`) |
| GET | `/api/orders/:id` | публичный | заказ по id |
| GET | `/api/orders/categories` | публичный | список категорий |
| POST | `/api/orders` | по токену | создать заказ |
| GET | `/api/orders/mine` | по токену | мои заказы |
| PATCH | `/api/orders/:id` | по токену, владелец | сменить статус (open/closed) |
| DELETE | `/api/orders/:id` | по токену, владелец | удалить заказ |

## Планы на мобильное приложение

Бэкенд — чистый REST API с JWT (без сессий/cookie), поэтому его можно напрямую
подключить к будущему приложению на React Native: авторизация, список заказов,
публикация заказа и переход в WhatsApp работают без каких-либо изменений на сервере.
