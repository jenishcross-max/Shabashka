# Шабашка.kg

Доска объявлений для поиска подработки и мастеров в Кыргызстане.

- **Заказчики** регистрируются (по email) и размещают заказы.
- **Исполнители** ничего не регистрируют — они просто смотрят заказы и пишут заказчику
  напрямую в WhatsApp кнопкой на странице заказа.
- Есть **админ-панель** для модерации (пользователи, заказы, жалобы).

Архитектура сделана как REST API + отдельный веб-фронтенд, чтобы тот же бэкенд
можно было потом переиспользовать для мобильного приложения на React Native.

## Стек

- **backend/** — Node.js, Express, SQLite (`better-sqlite3`), JWT-авторизация, `multer` (фото заказов)
- **frontend/** — React (Vite), React Router

## Возможности

- Регистрация/вход заказчиков по email, отдельный номер WhatsApp для связи
- Публикация заказов: категория, город, бюджет, фото
- Лента заказов: поиск, фильтр по категории/городу, сортировка (новые / по бюджету / популярные), пагинация
- Просмотры заказа, закреплённые ("🔥 Топ") заказы
- Избранное — работает без регистрации, хранится в `localStorage` браузера
- Редактирование/закрытие/удаление своих заказов, загрузка и замена фото
- Жалобы на заказы ("Пожаловаться") — без регистрации
- Админ-панель: статистика, пользователи (блокировка), заказы (скрыть/закрепить), жалобы (модерация)

## Локальный запуск

```bash
npm run install:all
```

В двух терминалах:

```bash
npm run dev:backend
```

```bash
npm run dev:frontend
```

Backend поднимется на `http://localhost:4000`, фронтенд — на `http://localhost:5173`
(Vite проксирует `/api` и `/uploads` на бэкенд, см. `frontend/vite.config.js`).

Скопируйте `backend/.env.example` в `backend/.env` и задайте свой `JWT_SECRET`.

### Демо-данные

```bash
cd backend
npm run seed
```

Полностью очищает базу и заполняет её реалистичными данными: ~13 пользователей,
~40 заказов по всем категориям и городам, несколько жалоб. Пароль всех демо-заказчиков —
`password123`. Админ создаётся тем же скриптом: `admin@shabashka.kg` / `admin12345`.

Чтобы создать/повысить администратора вручную:

```bash
npm run create-admin -- email пароль "Имя"
```

## Продакшн-сборка (один сервер)

```bash
npm run build
npm start
```

`backend/src/server.js` сам отдаёт собранный `frontend/dist` и загруженные фото
(`/uploads`) — то есть на проде достаточно одного сервиса, слушающего один порт
(`PORT`, по умолчанию 4000).

## Деплой на GitHub + Render

1. Запушьте репозиторий на GitHub.
2. На [render.com](https://render.com) создайте **New Web Service**, подключите репозиторий —
   Render подхватит `render.yaml` из корня (build: `npm run build`, start: `npm start`).
3. Render автоматически сгенерирует `JWT_SECRET`. При необходимости добавьте свои переменные окружения.
4. При каждом пуше в GitHub Render передеплоит сервис автоматически.

SQLite-файл и загруженные фото хранятся на диске сервиса (`backend/data`, `backend/uploads`,
примонтированы как persistent disk в `render.yaml`), поэтому данные переживают редеплой.

## API (кратко)

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/api/auth/register` | публичный | регистрация заказчика (email) |
| POST | `/api/auth/login` | публичный | вход |
| GET | `/api/auth/me` | по токену | текущий пользователь |
| GET | `/api/orders` | публичный | список заказов (фильтры: `category`, `city`, `q`, `sort`, `page`, `limit`) |
| GET | `/api/orders/batch?ids=1,2,3` | публичный | несколько заказов по id (для избранного) |
| GET | `/api/orders/:id` | публичный | заказ по id (увеличивает счётчик просмотров) |
| GET | `/api/orders/categories` | публичный | список категорий |
| GET | `/api/orders/category-counts` | публичный | количество открытых заказов по категориям |
| POST | `/api/orders` | по токену | создать заказ |
| GET | `/api/orders/mine` | по токену | мои заказы |
| PATCH | `/api/orders/:id` | по токену, владелец | обновить поля и/или статус |
| POST | `/api/orders/:id/photo` | по токену, владелец | загрузить/заменить фото |
| DELETE | `/api/orders/:id` | по токену, владелец | удалить заказ |
| POST | `/api/orders/:id/report` | публичный | пожаловаться на заказ |
| GET/PATCH | `/api/admin/*` | admin | статистика, пользователи, заказы, жалобы (см. `backend/src/routes/admin.js`) |

## Планы на мобильное приложение

Бэкенд — чистый REST API с JWT (без сессий/cookie), поэтому его можно напрямую
подключить к будущему приложению на React Native: авторизация, список заказов,
публикация заказа и переход в WhatsApp работают без каких-либо изменений на сервере.
