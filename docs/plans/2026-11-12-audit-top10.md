# Топ-10 аудита 12 ноября — план внедрения

> **Для Claude:** выполнять по задачам, тест сначала (test-driven-development), в
> конце — verification-before-completion. Бэкенд локально не запускать (в
> `backend/.env` боевая база); тесты — `cd backend && node --test test/*.test.js`
> (PGlite в памяти) и `cd frontend && npm test && npm run build`. Коммит — только по
> слову владельца, пуш — по «комит пуш».

**Цель:** откликов, подписок и своих вакансий становится больше, и всё это видно
в сводке бота. Источник — [docs/research/2026-11-audit.md](../research/2026-11-audit.md).

**Архитектура:** счётчики — те же `feedStats.bump` (таблица `bot_counters`) и
строки в `summary.js`. Короткие ссылки — правила `netlify.toml` → маршруты Render,
как у `/s/:slug`. Сайт о боте не знает — события через модуль-слушатель, как
`taskEvents.js`. Ручного времени владельца — ноль, число постов не уменьшается.

**Стек:** Node/Express + PGlite в тестах, React/Vite, Telegram Bot API, Threads/Instagram (Meta).

### Задача 1. Счётчик отклика (п.1)
- Создать `backend/src/routes/contact.js`, подключить в `server.js` как `/api/contact`.
  - `GET /vacancy/:id/:from?` — читает телефон (без `views + 1`), считает
    `contact.wa.<from>` (кроме роботов `BOT_UA_RE`), 302 на `wa.me/<цифры>?text=…`;
    нет номера или вакансии — 302 на карточку `PUBLIC_URL/vacancies/:id`.
  - `POST /:kind/:id` с `{ how: 'wa'|'tel', from }` — для `sendBeacon` с сайта:
    `contact.<how>.<from>`, ответ 204. `from` — из белого списка
    (`threads, telegram, bot, whatsapp, digest, direct`), иначе `direct`.
- `netlify.toml`: `/c/:id/:from` → `…/api/contact/vacancy/:id/:from` (302), выше SPA.
- Тест `test/contact-route.test.js`: редирект и счётчик; робот не считается;
  нет номера → карточка; POST считает и отдаёт 204; чужой `from` → `direct`.
