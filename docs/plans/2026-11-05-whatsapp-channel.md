# Автопостинг в WhatsApp-канал: план реализации

> **Для Claude:** выполнять по задачам, тест сначала (skill test-driven-development),
> перед словом «готово» — verification-before-completion.

**Цель:** бот сам выкладывает подборки вакансий в WhatsApp-канал Шабашки по
расписанию. Чем чаще в канале посты, тем охотнее WhatsApp показывает его в
«Обновлениях» тем, кто на него ещё не подписан.

**Архитектура:** бот на Render входит в WhatsApp как «связанное устройство»
второго номера, админа канала. Библиотека — неофициальная Baileys. Вход хранится
в Postgres: у бесплатного Render нет диска. Расписание сделано по образцу рубрик
Telegram (`telegram/rubrics.js`).

**Технологии:** Node 20, `@whiskeysockets/baileys@7.0.0-rc14` (ESM, грузится
через `import()`), Postgres/Supabase, тесты `node:test` и PGlite.

**Порядок работы:** коммит — только по просьбе владельца, деплой — только после
слов «комит пуш». Бэкенд локально не запускать: в `backend/.env` боевая база.

## ADR-1: автопостинг через Baileys со второго номера

**Статус:** принято владельцем 4.11.2026 («Бот сам, с отдельного номера», «через
рендер», «Да, делай здесь»)
**Дата:** 5.11.2026
**Решает:** владелец

### Контекст

- Канал «Жумуш | Работа | Шабашка» создан 4.11, описание и первый пост вышли.
  Владелец хочет постоянный поток вакансий: частые посты помогают попасть в
  рекомендации WhatsApp.
- У каналов WhatsApp **нет официального API для публикации**. WhatsApp Business
  API (Cloud API) пишет людям в личку, а не в каналы.
- Бэкенд живёт на бесплатном Render: диска нет, ночью с 01:00 до 05:00 спит,
  при деплое пару минут работают два экземпляра одновременно.
- Бюджет — ноль.

### Варианты

| | A. Baileys в боте, второй номер | B. Вручную владельцем | C. Расширение в Chrome (как Threads DM) |
|---|---|---|---|
| Сложность | средняя | нет | высокая |
| Цена | 0 (нужна SIM) | 2 мин владельца на пост | 0 |
| Надёжность | рвётся при обновлениях WhatsApp | зависит от владельца | только пока открыт компьютер |
| Риск | бан **второго** номера | нет | бан номера владельца |

### Решение

Вариант A. Номер отдельный, поэтому при бане теряется только он, а не WhatsApp
владельца. Постов мало, 5 в день в свой канал: для WhatsApp это не похоже на
рассылку.

### Последствия

- **Проще:** канал живёт сам, владельцу ничего делать не нужно.
- **Сложнее:** Baileys может сломаться после обновления WhatsApp. Тогда в сводке
  будет «не вышло», и библиотеку придётся обновить. Это не ломает остальной бот:
  WhatsApp подключается отдельно, и его ошибки не роняют процесс.
- **Память:** Baileys добавляет примерно 50–100 МБ к процессу, у Render free
  лимит 512 МБ. Если упрёмся — `WA_CHANNEL` пустой, и модуль не грузится вовсе.
- **Пересмотреть,** если у Meta появится официальный API каналов.

## Задачи

### Задача 1. Таблица `wa_auth`

**Файлы:** `backend/src/db/schema.sql` (в конец).

`wa_auth(key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TIMESTAMPTZ)`.
Ключ `creds` — сам вход, `<тип>-<id>` — ключи шифрования. Проверка — тест задачи 2:
PGlite прогоняет `schema.sql` целиком.

### Задача 2. Вход в базе — `src/whatsapp/auth.js`

**Тест:** `backend/test/whatsapp-auth.test.js` (PGlite и настоящий модуль Baileys).

1. Новый вход: `creds.registered === false`. После `saveCreds()` второй вызов
   `useDbAuthState` возвращает те же ключи, и они настоящие `Buffer`.
2. `keys.set` и `keys.get`: Buffer доходит целым; `null` удаляет ключ;
   отсутствующий ключ возвращает `null`.
3. `app-state-sync-key` возвращается объектом `proto` (с `keyData`).
4. `clear()` очищает таблицу.

**Код:** аналог `useMultiFileAuthState` из Baileys: чтение одним запросом
`key = ANY($1)`, запись — `unnest` с `ON CONFLICT`. Модуль Baileys передаётся
параметром (`lib`), потому что он ESM.

### Задача 3. Подключение — `src/whatsapp/channel.js`

**Тест:** `backend/test/whatsapp-channel.test.js`. Вместо Baileys — поддельный
модуль: сокет с `ev` (EventEmitter), `requestPairingCode`, `newsletterMetadata`,
`sendMessage` и `end`.

1. Номер не привязан — при старте не подключается, статус `unlinked`.
2. `link()` — на событии `qr` просит код для `WA_PHONE` (только цифры), отдаёт
   его; на `open` пишет админам «✅ WhatsApp привязан».
3. `post(text)` — ждёт `open` и один раз узнаёт канал по коду из ссылки
   `WA_CHANNEL` (`newsletterMetadata('invite', code)`). Шлёт
   `sendMessage('<id>@newsletter', { text })`; второй пост канал не переспрашивает.
4. Номер не админ канала (`viewer_metadata.role` = `SUBSCRIBER`) — `post`
   падает с понятной ошибкой.
5. `loggedOut` (401) — вход стирается, админам сообщение с `/whatsapp link`,
   статус `unlinked`, переподключения нет.
6. Обычный обрыв — переподключение с нарастающей паузой (5 с, 10 с, … до 5 мин).
7. `connectionReplaced` (440, второй экземпляр при деплое) — сам не
   переподключается, следующий `post` подключается заново.
8. Код не ввели и соединение закрылось — без повтора: каждый повтор присылал бы
   новый код.
9. `inviteCode` принимает и ссылку, и сам код.

### Задача 4. Подборки — `src/whatsapp/digest.js` и `freshVacancies`

**Файлы:** `src/rubricsRepo.js` (+`freshVacancies`), `src/whatsapp/digest.js`.
**Тесты:** `backend/test/whatsapp-digest.test.js` (заглушки, как в
`rubrics.test.js`) и проверка SQL `freshVacancies` на PGlite.

1. Слоты 9, 12, 15, 18, 21 по Бишкеку (`WA_HOURS`, `off` — выключено). Окно —
   2 часа от слота. Каждый слот — один раз: `claimSetting('wa:slot', 'день час')`.
2. В 15:00 — заказы (`freshOrders`), в остальные слоты — вакансии новее курсора
   `wa:last_vacancy_id`. После выхода курсор встаёт на самую свежую.
3. В тексте нет номеров. У каждой строки ссылка `шабашка.com/vacancies/<id>?s=w`,
   внизу ссылка на весь список. Звёздочки и подчёркивания из названий убраны: в
   WhatsApp это разметка.
4. Меньше трёх объявлений — пропуск (`wa.skip`), курсор не двигается.
5. Ошибка отправки — `wa.fail`, повтора в этом слоте нет. Ошибка базы — отметка
   снимается, следующий обход пробует снова.
6. `freshVacancies`: только открытые и не примеры, моложе 24 часов, id больше
   курсора, по одной на номер, свежие сверху.

### Задача 5. Бот — команда `/whatsapp`, запуск, сводка

**Файлы:** `src/whatsapp/index.js` (сборка и текст команды), `src/telegram/bot.js`
(команда и запуск рядом с `rubrics.start`), `src/telegram/commands.js` (кнопка в
меню админа), `src/telegram/summary.js` (строка «💬 WhatsApp: 4 · мало данных 1»),
`test/helpers/stub.js` (заглушка `whatsapp/index.js` в `exchangeStubs`, чтобы
тесты бота не грузили Baileys).
**Тесты:** `whatsapp-digest.test.js` (текст команды), `summary.test.js` (строка
сводки).

- `/whatsapp` — состояние, канал, расписание, последняя ошибка.
- `/whatsapp link` — код привязки и что с ним делать на втором телефоне.
- `/whatsapp now` — выложить подборку вакансий сейчас, вне расписания.

### Задача 6. README, `render.yaml`, `.env.example`

Переменные (`sync: false`):
- `WA_CHANNEL` — ссылка на канал; пусто — выключено;
- `WA_PHONE` — второй номер в международном формате;
- `WA_HOURS` — часы подборок.

В README — раздел «WhatsApp-канал»: как привязать, что в сводке, риски.

### Задача 7. Проверка

`cd backend && node --test test/*.test.js` — все тесты зелёные. Отдельно —
`cd frontend && node --test` для метки `w`.

### Владельцу после деплоя

1. Вставить SIM во второй телефон, установить WhatsApp и войти по этому номеру.
2. С основного номера добавить второй номер админом канала.
3. В Render задать `WA_CHANNEL` (ссылка на канал) и `WA_PHONE` (например,
   `996700123456`).
4. Написать боту `/whatsapp link` и ввести код на втором телефоне: «Связанные
   устройства» → «Привязка устройства» → «Привязать по номеру телефона».
5. Написать `/whatsapp now`: в канале должна появиться подборка.
