# Android-приложение «Шабашка — работа и мастера» — план реализации

> **For Claude:** Use `${SUPERPOWERS_SKILLS_ROOT}/skills/collaboration/executing-plans/SKILL.md` to implement this plan task-by-task.

**Goal:** Android-приложение на том же API, что и шабашка.com. Главное в нём — биржа услуг
(заказчик размещает задачу, исполнители откликаются с ценой, сроком и комментарием, заказчик
выбирает одного, после выбора — переписка); кроме того, в приложении можно смотреть обычные
заказы и вакансии и писать по ним в WhatsApp.

**Architecture:** Отдельный Expo-проект в `mobile/` того же репозитория. Экраны — Expo Router
(пять нижних вкладок со своими стеками), данные — TanStack Query поверх одного клиента
`src/api/client.js` (адрес API, токен, ошибки). Экраны — компоненты в `src/screens/`,
которые получают переходы колбэками; файлы в `src/app/` только связывают их с роутером — так
экраны тестируются без навигации. Правила биржи остаются на сервере (`backend/src/exchange.js`);
в приложении только подписи. На бэкенде — регистрация токенов и отправка пушей через
Expo Push API, удаление аккаунта (требование Google Play).

**Tech Stack:** Expo SDK 57 (React Native, React 19, Hermes), Expo Router, TanStack Query 5,
expo-secure-store, expo-notifications, Jest (`jest-expo`) + React Native Testing Library;
бэкенд — Node.js 24, Express 4, `node:test` + PGlite. Сборка — EAS Build в облаке Expo.

**Ограничения проекта:**
- Бэкенд локально НЕ запускать и не запускать скрипты, которые подключают `backend/src`
  с базой (в `backend/.env` боевая база). Только тесты: `cd backend && node --test test/*.test.js`.
- Секреты из `.env` не печатать. В аккаунты (Expo, Firebase, Google Play) не входить — это делает
  владелец; Google Play и сборки публикует сам владелец.
- Файлы в CRLF (после правок — `unix2dos` по своим файлам); комментарии по-русски, «зачем», а не «что».
- Коммит и пуш — только по команде владельца «комит пуш», каждый раз заново; в `master` без
  команды не сливать. В плане шагов «commit» нет.
- Зависимости — версии старше двух недель: ставить с `npm_config_before=<дата две недели назад>`
  (npm сам выберет последние версии на эту дату), в `package.json` — точные версии без `^`/`~`.
- Ветка `claude/musing-mclean-c4b1e1` стоит поверх ветки биржи `claude/exciting-davinci-142aaa`
  (коммит 2603bba): бэкенд пушей правит её код. Если в ветку биржи придут правки — перенести
  ветку на неё до работы с бэкендом.

**Поток данных.** Экран → хук TanStack Query (`useQuery`/`useInfiniteQuery`/`useMutation`) →
функция из `src/api/*.js` → `request()` → `fetch`. В тестах подменяется только `global.fetch`
(сеть) и SecureStore (нативный модуль) — свои модули не мокаем.

**Ошибки.** `request()` превращает ответ `{error, code}` в `ApiError(status, message, code)`;
текст сервера уже по-русски, экраны показывают его как есть. Нет сети — `ApiError(0, 'Нет связи
с сервером…')` и кнопка «Повторить». 401 при входе в аккаунт — выход и экран входа. 409 — текст
и перезагрузка данных экрана. Если ответа нет дольше 5 секунд — «Сервер просыпается, это до
минуты…» (Render засыпает).

```js
import { API_URL } from '../config';

// Ошибка API с текстом сервера: сервер уже пишет по-русски, экраны показывают как есть.
// status 0 — до сервера не дошли (нет сети).
export class ApiError extends Error {
  constructor(status, message, code) {
    super(message);
    this.status = status;
    this.code = code;
  }
}

// Токен живёт здесь, а не в контексте: request() вызывают и вне React (TanStack Query).
let token = null;
let onUnauthorized = () => {};

export function setToken(value) {
  token = value;
}

export function setUnauthorizedHandler(fn) {
  onUnauthorized = fn;
}

function toQuery(params = {}) {
  const pairs = Object.entries(params).filter(([, v]) => v !== undefined && v !== null && v !== '');
  if (!pairs.length) return '';
  return '?' + pairs.map(([k, v]) => `${encodeURIComponent(k)}=${encodeURIComponent(v)}`).join('&');
}

export async function request(path, { method = 'GET', body, query } = {}) {
  const headers = { Accept: 'application/json' };
  if (body !== undefined) headers['Content-Type'] = 'application/json';
  if (token) headers.Authorization = `Bearer ${token}`;

  let res;
  try {
    res = await fetch(API_URL + path + toQuery(query), {
      method,
      headers,
      body: body === undefined ? undefined : JSON.stringify(body),
    });
  } catch {
    throw new ApiError(0, 'Нет связи с сервером. Проверьте интернет и попробуйте ещё раз');
  }

  const data = await res.json().catch(() => ({}));
  if (!res.ok) {
    // 401 с токеном — токен истёк или аккаунт удалён; без токена это неверный пароль.
    if (res.status === 401 && token) onUnauthorized();
    throw new ApiError(res.status, data.error || `Ошибка сервера (${res.status})`, data.code);
  }
  return data;
}
```

**Step 3: Реализация** `src/auth/AuthContext.js`:

```js
import { createContext, useCallback, useContext, useEffect, useMemo, useState } from 'react';
import * as SecureStore from 'expo-secure-store';
import { setToken, setUnauthorizedHandler } from '../api/client';
import * as authApi from '../api/auth';

const KEY = 'auth';
const AuthContext = createContext(null);

// status: 'loading' — читаем SecureStore, 'guest' — не вошёл, 'user' — вошёл.
export function AuthProvider({ children }) {
  const [state, setState] = useState({ status: 'loading', user: null });

  const signOut = useCallback(async () => {
    setToken(null);
    await SecureStore.deleteItemAsync(KEY);
    setState({ status: 'guest', user: null });
  }, []);

  const remember = useCallback(async ({ token, user }) => {
    setToken(token);
    await SecureStore.setItemAsync(KEY, JSON.stringify({ token, user }));
    setState({ status: 'user', user });
  }, []);

  useEffect(() => {
    setUnauthorizedHandler(signOut);
    let alive = true;
    (async () => {
      const saved = JSON.parse((await SecureStore.getItemAsync(KEY)) || 'null');
      if (!saved) return alive && setState({ status: 'guest', user: null });
      setToken(saved.token);
      if (alive) setState({ status: 'user', user: saved.user });
      try {
        const { user } = await authApi.me();
        if (alive) await remember({ token: saved.token, user });
      } catch {
        // 401 уже вызвал signOut через client; нет сети — остаёмся с сохранённым.
      }
    })();
    return () => {
      alive = false;
    };
  }, [signOut, remember]);

  const signIn = useCallback(async (email, password) => remember(await authApi.login(email, password)), [remember]);
  const signUp = useCallback(async (fields) => remember(await authApi.register(fields)), [remember]);

  const value = useMemo(() => ({ ...state, signIn, signUp, signOut }), [state, signIn, signUp, signOut]);
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export const useAuth = () => useContext(AuthContext);
```

### Task 17: Бэкенд — токены пушей

**Files:** `backend/src/db/schema.sql` (блок в конец файла), `backend/src/pushRepo.js`,
`backend/src/routes/push.js`, `backend/src/server.js` (`app.use('/api/push', …)`);
Test: `backend/test/push-repo.test.js`, `backend/test/push-route.test.js` (PGlite, как
`tasks-repo.test.js` и `tasks-route.test.js`)

```sql
-- Токены Expo для пушей в Android-приложение. Один телефон — один владелец:
-- вошёл другой человек — токен переходит к нему (ON CONFLICT в pushRepo.save).
CREATE TABLE IF NOT EXISTS push_tokens (
  token      TEXT PRIMARY KEY,
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS push_tokens_user_idx ON push_tokens(user_id);
```

`pushRepo`: `save(userId, token)` (upsert, переписывает `user_id`), `remove(userId, token)`
(только свой), `forUsers(ids)`, `drop(tokens)`. Роут: `POST /api/push/token {token}` и
`DELETE /api/push/token {token}`, оба `requireAuth`; токен — строка вида
`ExponentPushToken[...]` (иначе 400). Тесты: сохранение, переход токена к другому человеку,
удаление чужого токена не срабатывает, неверный формат — 400, без входа — 401.

### Task 18: Бэкенд — отправка пушей и события

**Files:** `backend/src/push.js`, `backend/src/routes/tasks.js`, `backend/src/routes/conversations.js`;
Test: `backend/test/push.test.js`, дополнить `backend/test/tasks-route.test.js`

`push.js`: `notify(userIds, { title, body, data })` — берёт токены (`pushRepo.forUsers`), шлёт
пачками до 100 на `https://exp.host/--/api/v2/push/send` обычным `fetch` (Node 24), без
`await` в обработчике запроса (`notify(...).catch(log)`): сбой пуша не должен ронять ответ.
Токены с ответом `DeviceNotRegistered` — `pushRepo.drop`. Текст сообщения в пуше обрезается
до 100 символов. События:
- `POST /api/tasks/:id/offers` — новый отклик (отклика не было или он был отозван; правка —
  без пуша) → заказчику: заголовок «Новый отклик», текст «На «<задача>»: <цена> сом, <срок>»,
  `data: { url: 'shabashka:///tasks/<id>' }`;
- `POST /api/tasks/:id/offers/:offerId/accept` → исполнителю: «Вас выбрали исполнителем»,
  «<задача>», `data: { url: 'shabashka:///messages/<conversation_id>' }`. Первое
  автоматическое сообщение отдельного пуша не даёт (оно пишется в `tasksRepo.accept`, мимо роута
  сообщений);
- `POST /api/conversations` и `POST /api/conversations/:id/messages` → собеседнику: заголовок —
  имя отправителя, текст — начало сообщения, `data: { url: 'shabashka:///messages/<id>' }`.

Тесты: `global.fetch` подменён (внешний сервис), проверяется, кому и что ушло; правка отклика
пуш не шлёт; `DeviceNotRegistered` удаляет токен; ошибка Expo не меняет ответ роута.

## Что не входит

- iOS (Expo позволяет позже, но нужен аккаунт Apple и отдельная публикация).
