# Раздел «Объявления» на шабашка.com — план реализации

> **For Claude:** Use `${SUPERPOWERS_SKILLS_ROOT}/skills/collaboration/executing-plans/SKILL.md` to implement this plan task-by-task.

**Goal:** Новый раздел «Объявления»: люди с аккаунтом подают объявления «Сдам / Сниму /
Продам / Куплю / Отдам даром» по рубрикам (жильё, отдых и пансионаты, транспорт…), с ценой,
городом, WhatsApp и до 6 фото; остальные ищут их по фильтрам и пишут автору в WhatsApp или
в «Сообщения» сайта.

**Architecture:** Отдельная таблица `ads` (не `orders` и не `board_posts`: их читают бот,
автопостинг, рубрики и sitemap — объявление не должно туда утечь). Правила — чистые функции
в `adsRules.js`, SQL — `adsRepo.js`, HTTP — `routes/ads.js` (`/api/ads`). Фото — в Supabase
Storage (публичное хранилище `ads`): бэкенд выдаёт одноразовую ссылку на загрузку, браузер
ужимает фото и грузит его прямо в Supabase, мимо Render. Жалобы, журнал модерации, переписка
и избранное переиспользуются через `listing_type = 'ad'`.

**Tech Stack:** Node.js 24, Express 4, Postgres (Supabase), Supabase Storage (REST, без SDK),
`node:test`, PGlite (только тесты), React 18 + React Router 6 (Vite).

**Ограничения проекта:**
- Бэкенд локально НЕ запускать, скрипты с `backend/src` и базой не запускать (в
  `backend/.env` боевая база). Только тесты: `cd backend && node --test test/*.test.js`.
- База в тестах — PGlite через `test/helpers/stub.js`; хранилище в тестах — заглушка или
  подставной `fetch`, в Supabase тесты не ходят.
- Файлы в CRLF (после правок — нормализация скриптом); комментарии по-русски, «зачем».
- Коммит и пуш — только по команде владельца «комит пуш». Шагов «commit» в плане нет.
- `schema.sql`, `README.md` параллельно правит другая сессия: свои блоки — только в конец.
- В соцсети и каналы объявления не уходят (решено: «пока механику делаем»).

## Решения из обсуждения (2026-10-16)

| Вопрос | Решение |
|---|---|
| Название | «Объявления»; в меню «Подработка» пункт «Все объявления» → «Все заказы»; в шапке «Мои объявления» → «Мои публикации» (+ вкладка «Объявления») |
| Разметка | Вид (Сдам / Сниму / Продам / Куплю / Отдам даром) + рубрика + город + поиск |
| Рубрики | Жильё · Отдых · Транспорт · Техника и электроника · Дом и стройка · Одежда и вещи · Животные · Другое |
| Фото | До 6, Supabase Storage, сжатие в браузере до 1280 px |
| Кто подаёт | Только с аккаунтом; связь — WhatsApp (если указан) и переписка на сайте |
| Срок | Без срока, как заказы: открыто, пока автор не закроет; «поднять» раз в сутки |
| Цена | Сумма в сомах + «за всё / за сутки / за месяц / за час»; пусто — «Договорная»; у «Отдам даром» цены нет |
| Соцсети | Не публикуем; позже отдельным решением |
| Главная | Блок «Свежие объявления» (4 шт.) под блоком биржи |

Коды в API (их же возьмёт Android-приложение):
- `kind`: `rent_out` Сдам · `rent` Сниму · `sell` Продам · `buy` Куплю · `free` Отдам даром
- `category`: `housing` · `rest` · `transport` · `tech` · `home` · `things` · `animals` · `other`
- `price_unit`: `total` · `day` · `month` · `hour`
- `status`: `open` · `closed` (закрыл автор, может открыть снова) · `removed` (снял модератор)

### Task 1: Таблица `ads`

**Files:**
- Modify: `backend/src/db/schema.sql` — новый блок В КОНЦЕ файла

**Step 1:** Дописать блок:

```sql
-- Объявления: сдам, сниму, продам, куплю, отдам даром. Отдельная таблица, а не
-- orders и не board_posts: те читают бот, автопостинг и рубрики, а объявления
-- пока живут только на сайте. photos — пути в хранилище Supabase, первый — обложка.
CREATE TABLE IF NOT EXISTS ads (
  id             SERIAL PRIMARY KEY,
  user_id        INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  kind           TEXT NOT NULL,              -- rent_out | rent | sell | buy | free
  category       TEXT NOT NULL,              -- housing | rest | transport | tech | home | things | animals | other
  title          TEXT NOT NULL,
  description    TEXT NOT NULL,
  price          BIGINT,                     -- сомы; NULL — «договорная» или «даром»
  price_unit     TEXT,                       -- total | day | month | hour; NULL, если цены нет
  city           TEXT NOT NULL,
  address        TEXT,
  whatsapp_phone TEXT,
  photos         JSONB NOT NULL DEFAULT '[]',
  status         TEXT NOT NULL DEFAULT 'open', -- open | closed | removed
  views          INTEGER NOT NULL DEFAULT 0,
  bumped_at      TIMESTAMPTZ,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_ads_feed ON ads(status, (COALESCE(bumped_at, created_at)) DESC);
CREATE INDEX IF NOT EXISTS idx_ads_user ON ads(user_id);
```

**Step 2:** Проверка — тесты Task 3 (PGlite выполняет весь `schema.sql`).

**API:**

| Метод | Путь | Кто | Что |
|---|---|---|---|
| GET | `/api/ads` | все | лента: `kind, category, city, q, priceMin, priceMax, sort=new\|cheap\|expensive, page, limit` |
| GET | `/api/ads/mine` | автор | все свои |
| GET | `/api/ads/batch?ids=` | все | для избранного, без снятых |
| GET | `/api/ads/:id` | все | снятое модератором видит только автор; просмотр автора не считается |
| POST | `/api/ads` | с аккаунтом | создать (лимит, подтверждение почты для второго) |
| PATCH | `/api/ads/:id` | автор | править; убранные из списка фото удаляются из хранилища |
| POST | `/api/ads/:id/close` · `reopen` · `bump` | автор | закрыть, открыть снова, поднять раз в сутки |
| DELETE | `/api/ads/:id` | автор | удалить вместе с фото |
| POST | `/api/ads/photos` | с аккаунтом | одноразовая ссылка на загрузку: `{ path, upload_url, url }`; 503, если хранилище не настроено |
| POST | `/api/ads/:id/report` | все | жалоба |
| POST | `/api/conversations` | с аккаунтом | `{ adId, message }` — написать автору |

Фото в ответах — `[{ path, url }]`: путь нужен форме правки, ссылка — показу.

**Тесты:** гость видит ленту и объявление, но подать не может (401); неполное — 400; чужие
фото — 400; правка и переходы чужим — 403; снятое модератором — 404 гостю, автору видно;
`bump` дважды — 429; удаление зовёт `remove` хранилища с путями; `/photos` — 503 без
хранилища и ссылка с путём `u<id>/…` с ним; жалоба создаёт `reports` и уведомление; админ
«скрыть» → `removed`, из ленты пропало; переписка по объявлению создаётся, по закрытому —
400; второе объявление без подтверждённой почты — 403.

## Как сделано (2026-10-16)

- Всё по плану; отличия по ходу: цена — `INTEGER`, а не `BIGINT` (драйвер Postgres отдаёт
  `BIGINT` строкой, а до предела в миллиард хватает и `INTEGER`); пары «путь + ссылка» для
  фото собирает `adsView.js` — их отдают и `/api/ads`, и главная.
- В HTTP-тестах лимиты по адресу выключены (весь файл ходит с одного 127.0.0.1), а колонку
  `is_example`, которую добавляет `db/index.js`, тест главной создаёт сам.
- На телефоне четвёртая вкладка «Моих публикаций» выходила за край — отступы ужаты для всех
  вкладок; поля «Цена от / до» держатся в одну строку.
- Проверка: `npm test` — 342/342 (36 новых), `npm run build` — без ошибок; экраны на
  заглушке API — лента, фильтры, страница, «Мои объявления», подача с загрузкой фото
  (сжатие 4000×3000 → 1280×960 JPEG), ширина 375 px без горизонтальной прокрутки.
